# Web の UI 文言（i18n）

仕様の出どころ: issue #703（設計書 §2〜§6 の要約）。UI の文言は `t(key)` で辞書から引く。
言語は `ja` / `en`、`ja` の上書きとして `ja-kansai`（関西弁。設定 UI は別 PR）。

## 構成（`web/src/i18n/`）

| ファイル | 役割 |
|---|---|
| `locale.ts` | zustand ストア。`nostrism.locale`（`auto`/`ja`/`en`、既定 `auto`、不正値は `auto`）と `nostrism.kansaiMode`（`on`/`off`、既定 `off`）。`resolveLocale(setting, kansai, languages)` は純関数（auto は先頭の言語が `ja*` なら ja、他は en。関西弁は ja のときだけ `ja-kansai`）。`initLocale()` が `<html lang>`（ja/en）と `data-dialect="kansai"`（オン時のみ）を当て、`languagechange` で再解決する。NIP-78 には同期しない |
| `index.ts` | `t(key, ...args)` と `useT()`（言語の変更で再描画）。辞書の引き順は `ja-kansai → ja`、`en → ja`。`%1$s` / `%2$d`（位置指定）・`%s`（順番）・`%%`。引数が足りない指定はそのまま残す。未知キーは本番ではキー文字列を返して warn、テストでは throw |
| `format.ts` | `formatNumber` / `formatDateTimeLocal`（言語に合わせた Intl）。`lib/time.ts` は言語非依存なので触らない |
| `native.ja.json` / `native.en.json` | **生成物**（手で編集しない）。`scripts/import-strings.mjs` が書く |
| `web.ja.json` / `web.en.json` | Web 固有の文言（キーは `web_` 始まり）。手書き。en に無いキーは ja で出る |
| `ja-kansai.json` | 関西弁。`ja` と違うキーだけ。native / web 共通の 1 枚 |

テストは `src/test/setup.ts` で `nostrism.locale` を `ja` に固定する（jsdom の言語は `en-US`）。

## キー命名

- ネイティブ（`composeApp/.../values-ja/strings.xml`）に同じ意味の文言がある: **そのキー名をそのまま**使う（`nyan_mode_title` など）。
- Web 固有: `web_<画面>_<意味>`（例 `web_display_datasaver_title`）。英語は手書き。
- 1 画面要素 1 キー。文を分割しない（英語・関西弁は語順が変わる）。動的な語は位置指定書式（`%1$s`）。
- `title` / `aria-label` / `placeholder` も `t()` を通す。
- 保存値・同期値（カラムの正準タイトルなど）は変えない。表示だけ訳す。

## 辞書の増やし方・移行の手順

1. 対象ファイルの日本語リテラルを洗い出す。ネイティブに同じ文言があるか `node scripts/import-strings.mjs --candidates`（Web の日本語と values-ja の値が完全一致するもの）で確かめる。
2. ある → そのキーで `t("key")`。無い → `web_*` のキーを `web.ja.json` に **今の日本語そのまま**（1 字も変えない）で足す。
3. `node scripts/import-strings.mjs` で `native.ja.json` / `native.en.json` を更新してコミットする（`t()` で参照しているキーだけが入る。strings.xml は読むだけ。Kotlin / Gradle は動かさない）。`--check` で最新か確かめられ、`src/i18n/scripts.test.ts` が同じことをテストする。
4. 動的な `t(variable)` は import-strings の対象にならない（リテラルのキーだけ拾う）。キーは文字列リテラルで書く。
5. 既存テストは書き換えない（`ja` の値が変わっていない担保）。

## lint

`node scripts/check-i18n.mjs`（`npm run check` は biome の後にこれを実行する）。`web/src` の本体コード **全ファイル** で、日本語（ひらがな・カタカナ・漢字）を含む文字列リテラル・テンプレート・JSX テキスト・正規表現リテラルが残っていたら非 0。コメントは無視する。
除外: テスト（`*.test.ts(x)`）、`src/test/`、`src/i18n/`（辞書と `columnTitles.ts`）、`emojiCatalog.ts`（絵文字の検索語）、`ui/nyan.ts`（「にゃいず」の置換規則）。限界: JSX テキスト中の `'` や `//` は文字列・コメントの開始と見なす。

## カラムのタイトル（`i18n/columnTitles.ts`）

カラムのタイトル・サブタイトルは DB と NIP-78 に保存・同期されるので、日本語の正準値（`CANONICAL_TITLE` / `CANONICAL_SUBTITLE`）をそのまま保存する（ネイティブの `ColumnTitles.kt` と同じ対応表）。表示だけ `columnDisplayTitle(title)` / `columnDisplaySubtitle(subtitle)`（`lib/columns.ts` の `columnLabel(spec)` / `columnSubtitleFor(spec)`）が辞書を引く。一致しない文字列（タグ・検索要約・プロフィール名）はそのまま。テンプレ名・ヒントは `templateLabel` / `templateHint`、通知種別は `notifKindLabel`。

## ネイティブとの関係

`en` / `ja` はネイティブが正で、`native.*.json` は strings.xml の写し（戻すものは無い）。`web_*` で後にネイティブにも要る語が出たら、ネイティブの strings.xml に同名キーで足し、Web は `import-strings.mjs` 経由で native 側へ移す。`ja-kansai.json` は flat `{ key: string }`・strings.xml のキー・`%1$s` 書式に限る。
