fix: RPM 判定を rpmbuild 基準に直し、Linux 前提ツールを README に追記

## 1. [バグ] release-desktop.sh の RPM 判定が甘かった

`command -v rpmbuild || command -v rpm` で判定していたため、
`rpmbuild` が無い環境（rpm-build を入れていない Fedora 等）でも
`rpm` 本体があるので「RPM ビルド可能」と誤判定し、`packageRpm` を
必ず実行して失敗していた。jpackage が実際に呼び出すのは `rpmbuild` だけ
なので、`command -v rpmbuild` 単一で判定するよう修正。

## 2. README に Linux 前提ツールと WSL の注意を追記

- ディストリ別の必要パッケージ:
  - Debian/Ubuntu: DEB=apt install fakeroot / RPM=apt install rpm
  - Fedora/RHEL  : RPM=dnf install rpm-build
- rpmbuild に入れ忘れやすい点（rpm 本体は Fedora 標準で入っているため、
  存在判定だけだと入れ忘れに気付けない）を明記
- WSL で package* が失敗する既知の制約を追記:
  - NTFS マウント（/mnt/c, /mnt/g 等）上では jlink/jpackage が legal/ 配下に
    特殊ファイルを作れず Operation not permitted になる
  - ext4/btrfs（~）上に clone してビルドする
  - root でビルドした実績がある場合は所有者を戻す
